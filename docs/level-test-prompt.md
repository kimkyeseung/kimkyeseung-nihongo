# 구현 프롬프트 — 레벨 진단(`/level`) 신설 + `/test` 재기획

> 이 문서는 구현을 맡길 때 그대로 넘기는 프롬프트다. 먼저 `CLAUDE.md` 전체(특히 "핵심 규칙",
> "테스트", "선생님 `/` 명령어", "선생님 연습해보기", "커리큘럼 / 오늘의 학습", "학습자 기억",
> "백업", "페이지를 새로 추가할 때")를 읽고 시작할 것. 이 문서와 CLAUDE.md가 어긋나면 CLAUDE.md의
> 규칙이 이긴다 — 어긋나는 걸 발견하면 구현 전에 물어볼 것.

---

## 0. 배경 — 왜 다시 만드나

지금 `/test`(`levelTest.ts`)는 **코드가 출제 범위만 정하고, 문제 문장은 온디바이스 모델이 쓴다.**
그래서 "연습해보기" 절에 적힌 문제가 그대로 따라온다 — 정답을 틀리게 달고, 형식을 어기고, 3~5문제라
수준을 재기에는 너무 짧다. 게다가 범위의 절반이 "약한 것"이라 수준 테스트가 아니라 `/review`에 가깝다.

두 기능으로 나눈다:

| | **`/level` — 레벨 진단 (신설)** | **`/test` — 단원 점검 (재기획)** |
|---|---|---|
| 상황 | 선생님과 학생이 처음 만났을 때. 또는 "내가 지금 어느 정도지?" | 지금 커리큘럼 단원을 다 했는지 확인 |
| 범위 | N5~N1 전체, 다섯 영역 | 지금 단원 하나(문법·한자·어휘) |
| 시간 | 10~15분 | 3~5분 |
| 결과 | 영역별 추정 급수 + 종합 → 커리큘럼 시작 단계 | 통과하면 그 단원 완료 처리 제안 |
| 화면 | **전용 페이지 `/level`** | 기존 `TeacherPracticeSheet` 자리의 바텀시트 |

**두 기능 모두 문제는 코드가 낸다(LLM 없음).** 모델은 끝에 선생님 총평 한 번만 쓴다.
→ AI를 못 쓰는 브라우저(Whale·Firefox 등)에서도 진단과 점검이 돈다. 총평만 빠진다.

## 1. 이름

- 명령어: **`/level`**, 한글 별칭 `/레벨`·`/레벨테스트`·`/진단`.
- 라우트: **`/level`**.
- `/diagnostic(s)`은 쓰지 않는다 — **이미 `/diagnostics`(Prompt API 자가진단) 페이지가 있다.**
  이름이 거의 같으면 링크·명령어·문서에서 계속 헷갈린다.
- `/test`는 이름 그대로 두고 내용을 "단원 점검"으로 바꾼다(별칭 `테스트`·`시험`·`점검` 추가).

## 2. 원칙 (이 기능에서 특히 지킬 것)

1. **정답이 정해진 문제는 전부 정적 데이터에서 만든다.** 어휘 뜻·한자 읽기는 `dictionary.json`·
   `kanji.json`, 문법·독해·청해는 **이번에 손으로 정리하는 문제 은행**(3절). 모델에게 문제·정답·보기를
   쓰게 하지 않는다.
2. **급수를 지어내지 않는다.** `jlptLevel: null`(급수 외) 단어는 출제·보기에서 뺀다.
3. **보기는 정답과 같은 언어로만** 고른다(약한 것 모아 풀기에서 실제로 겪은 문제 — 한국어 정답 +
   영어 오답이면 뜻을 몰라도 맞힌다). 한국어 뜻이 없는 단어는 어휘 영역 출제에서 뺀다.
4. **학습 기록(`recordStudyEvent`)에 문제별 결과를 남기지 않는다.** 진단은 일부러 실력 위 급수를
   묻는 시험이라, 틀린 N1 단어를 "약한 단어"로 넣으면 `/review`가 엉뚱한 단어로 찬다. 결과는
   **요약(영역별 급수)만** 따로 저장한다(6절).
5. 조용히 틀리는 계산(적응 알고리즘·급수 판정·출제·채점·은행 데이터 검사)은 **순수 함수로 떼고
   vitest로 고정한다.** CLAUDE.md "테스트" 목록에 추가할 것.
6. 총평 LLM 호출에는 4중 방어를 전부 건다(`wrapStudentText`는 넣을 학습자 입력이 없으니 해당 없음 —
   대신 프롬프트에 들어가는 건 코드가 만든 숫자뿐이어야 한다. 학습자가 친 글자를 넣지 말 것).

## 3. 데이터 — 손으로 정리하는 문제 은행 `src/data/level-test-bank.json`

`curriculum.json`과 같은 성격(**손으로 만든 데이터, `scripts/data` 파이프라인 밖**)이다.
출처 표기 규칙도 커리큘럼과 같다 — `/about`·README·`scripts/data/README.md` 세 곳에 "직접 정리한
문제, JLPT 공식 문제 아님"을 적는다(라이선스 표가 아니라 커리큘럼 문단 옆).

**JLPT 기출·시판 문제집 문장을 옮기지 말 것.** 저작권이 있다. 문형은 커리큘럼·JLPT 공개 기준을
참고하되 문장은 새로 쓴다.

### 3-1. 스키마 (초안 — 구현 전에 타입부터 `src/types/levelTest.ts`에)

```ts
type JlptLevel = "N5" | "N4" | "N3" | "N2" | "N1";

type GrammarItem = {
  id: string;                 // "g-n4-001"
  level: JlptLevel;
  pattern: string;            // curriculum.json의 grammarPoints[].pattern과 같은 문자열(점검이 이걸로 찾는다)
  sentence: string;           // 빈칸은 「＿＿」 하나. 예: "雨が降っ＿＿、試合は中止になった。"
  choices: string[];          // 정확히 4개. 정답 1 + 오답 3
  answer: number;             // choices의 인덱스
  translation: string;        // 정답을 넣은 문장의 한국어 번역(결과 화면 해설용)
  note?: string;              // 왜 다른 보기가 안 되는지 한 줄(선택)
};

type ReadingItem = {
  id: string;
  level: JlptLevel;
  passage: string;            // N5 2~3문장 … N1 6~8문장
  question: string;           // 한국어 질문
  choices: string[];          // 한국어 4개
  answer: number;
};

type ListeningItem = {
  id: string;
  level: JlptLevel;
  script: { speaker?: "A" | "B"; text: string }[];  // TTS로 읽을 대사. 화면에는 안 보인다(풀고 나서만)
  question: string;           // 한국어 질문(화면에 보인다)
  choices: string[];          // 한국어 4개
  answer: number;
};

type LevelTestBank = {
  meta: { version: number; note: string };
  grammar: GrammarItem[];
  reading: ReadingItem[];
  listening: ListeningItem[];
};
```

### 3-2. 분량 목표

| 급수 | 문법 | 독해 | 청해 |
|---|---|---|---|
| N5 | 35 | 4 | 5 |
| N4 | 35 | 4 | 5 |
| N3 | 35 | 4 | 5 |
| N2 | 35 | 4 | 5 |
| N1 | 35 | 4 | 5 |

- 문법은 적응형으로 한 번에 10~12문항을 쓰고, 같은 급수에서 최대 4~5개가 연달아 나올 수 있으니
  급수당 35개면 "다시 보기"를 두세 번 해도 겹치지 않는다.
- **N5~N4 문법 항목은 커리큘럼의 `grammarPoints` 패턴을 전부 한 번 이상 덮을 것** — `/test` 단원
  점검이 같은 은행을 쓴다(7절). N3 이상도 가능한 한 커리큘럼 패턴에 맞춘다.
- 데이터는 한 번에 다 만들지 말고 **급수 하나씩 만들어 보여주고 검토받는다**(9절 단계 1).

### 3-3. 은행 데이터 검사 (`levelTestBank.test.ts`) — 커리큘럼 검사와 같은 방식

- `sentence`에 `＿＿`가 **정확히 하나**, `choices`는 4개이고 서로 다르며 `answer`가 범위 안.
- 정답을 빈칸에 넣은 문장에 영문 알파벳이 섞이지 않음(`毎日japanese勉強` 같은 깨진 예문 방지 —
  커리큘럼에서 실제로 있었다).
- `translation`·독해/청해의 `question`·`choices`에 한글이 있음, 가나는 없음.
- `pattern`이 커리큘럼에 있는 문자열이면 그 패턴의 `level`과 항목의 `level`이 같음(다르면 이유를
  `note`에 적고 허용 목록으로).
- N5·N4 커리큘럼 `grammarPoints`가 전부 은행 어딘가에 `pattern`으로 있음(빠지면 단원 점검 출제가
  비는 단원이 생긴다).
- id 중복 없음, 급수별 개수가 3-2의 최소치 이상.
- 청해 `script`의 `text`에 한글이 없음(TTS가 읽는다).

## 4. `/level` — 레벨 진단

### 4-1. 화면 흐름 (`src/pages/LevelTestPage.tsx`, 라우트 `/level`)

헤더 아이콘은 늘리지 않는다(이미 둘이 한계). 입구는 셋:
1. 선생님 입력창의 `/level`(→ `navigate("/level")`).
2. 대문 "오늘의 학습" 카드에서 시작 단계를 묻는 자리 — "잘 모르겠어요 → 10분 진단 받기".
3. `/curriculum` 화면 상단 링크(시작 단계 바꾸기 옆).

단계:

1. **인사** — 선생님이 처음 만난 것처럼 맞이한다(문구는 코드가 만든다. 모델 아님 — "인사는 앱이
   한다" 규칙). 소요 시간(10~15분), 영역 다섯, **소리가 나온다**(청해)는 안내, "모르면 모르겠어요를
   눌러도 된다 — 찍으면 결과가 부정확해진다". 시작 버튼.
2. **(선택) 두 가지 질문** — 공부 목적(여행/시험/일/취미/기타), 목표 시험 일정(없음/급수+시기).
   버튼으로만 고른다(자유 입력 없음 → 인젝션 걱정 없음). 고르면 **기억 확인 칩 흐름과 같은
   `pending` 사실**로 넣지 말고, 학습자가 고른 것이므로 바로 `confirmed` 기억으로 넣는다
   (`sanitizeMemoryLine` 통과). 건너뛰기 가능.
3. **영역 순서대로 풀기** — 문자(조건부) → 어휘 → 한자 → 문법 → 독해 → 청해.
   - 상단: 전체 진행 바 + 지금 영역 이름 + 경과 시간(제한 아님, 표시만).
   - 모든 문제는 **4지선다 + "모르겠어요"**. 입력형은 없다(15분 안에 끝내야 하고, 채점 애매함을
     없애려고).
   - 답을 고르면 정답/오답을 **보여주지 않고** 바로 다음 문제(진단 중 피드백은 다음 문제 판단을
     흔든다). 해설은 결과 화면에서.
   - 영역이 바뀔 때 짧은 전환 화면("다음은 한자예요").
4. **결과** — 6절.

**나가기·탭 이동**: 진행 상태는 `pageStateStore`에 메모리 전용 스토어(`useLevelTestSession`)로 둔다
— 탭을 옮겼다 와도 이어서 풀린다. 새로고침하면 처음부터(15분짜리를 persist까지 하진 않는다).
진행 중에 헤더 로고·하단 네비로 나가려 하면 막지 말고, 돌아왔을 때 "이어서 풀기 / 처음부터"를 묻는다.

### 4-2. 적응 알고리즘 (`src/lib/levelTest/adaptive.ts` — 순수 함수, 테스트 필수)

영역마다 독립적으로 돈다. 상태는 직렬화 가능한 순수 값으로.

```
시작 급수: N4 (문자 영역 제외)
  - 커리큘럼 startLevel 또는 learnerProfile.levelGuess가 있으면 그 급수에서 시작
매 문항:
  - 맞힘  → streak +1, streak가 2가 되면 한 급수 위로(N1이면 그대로), streak 0
  - 틀림/모르겠어요 → 한 급수 아래로(N5면 그대로), streak 0
종료(영역별):
  - 방향이 바뀐 횟수(올라가다 내려감 또는 반대)가 3번 → 종료
  - 또는 영역 최대 문항 수 도달
  - 또는 N5에서 2개 연속 틀림 → 종료하고 "문자 영역 필요" 표시
추정 급수:
  - 급수별 (맞힌 수, 푼 수)를 모은다
  - "그 급수에서 2문항 이상 풀었고 정답률 ≥ 2/3"인 급수 중 가장 높은 것
  - 하나도 없으면 "N5 미만"(= Pre-N5)
```

영역별 문항 상한(시간 예산 합 ≈ 15분):

| 영역 | 상한 | 문항당 | 예산 |
|---|---|---|---|
| 문자(가나) | 8 | 10초 | ~1.5분 (조건부) |
| 어휘 | 12 | 20초 | ~4분 |
| 한자 읽기 | 10 | 20초 | ~3분 |
| 문법 | 12 | 30초 | ~6분 |
| 독해 | 2 | 60~90초 | ~2.5분 |
| 청해 | 3 | 40초 | ~2분 |

- **문자 영역**은 처음엔 건너뛴다. 어휘가 N5에서 종료되거나 N5 정답률이 1/2 미만이면 끝에 붙인다.
- **독해·청해는 문항이 적어 계단식이 안 된다.** 문법·어휘 추정치 중 낮은 쪽 급수의 문제로 시작해
  맞히면 한 급수 위 문제, 틀리면 한 급수 아래 문제를 하나 더. 추정 규칙은 같다(2문항 중 1개
  이상 맞힌 가장 높은 급수 — 문항이 적으니 기준을 "푼 문항의 절반 이상"으로).
- 같은 진단 안에서 같은 문제·같은 정답 단어/한자를 두 번 내지 않는다.

테스트로 고정할 것: 계단 이동, 종료 조건 세 가지, 추정 규칙(경계값 2/3), N1/N5 끝에서 안 넘어감,
시작 급수 결정, 문자 영역 붙는 조건, 독해·청해 2문항 규칙.

### 4-3. 영역별 출제 (`src/lib/levelTest/questions.ts` — 순수 함수, 데이터는 인자로)

- **어휘** — `dictionary.json`에서 그 급수 + `common` + 한국어 뜻 있는 단어. 질문은 표기(한자어면
  후리가나 없이), 보기는 한국어 뜻 4개(`shortMeaning` 재사용). 오답은 **같은 급수 같은 품사 계열**에서,
  보기끼리 겹치지 않게. 다의어로 오답이 정답 뜻과 겹치면 다시 뽑는다.
  - 사전은 7.7MB라 페이지에서 동적 import. 페이지 진입 때 받으면서 인사 화면을 보여준다.
- **한자 읽기** — `kanji.json` 급수 → `kanjiQuiz`의 `primaryReading`/`wordsContaining`로
  **단어 속 읽기**를 묻는다(「水曜日」의 水 → すい). 한 글자 단독보다 실제 시험에 가깝다. 오답 읽기는
  기존 `buildKanjiQuiz`의 보기 규칙 재사용. kanjivg는 필요 없다.
- **문법** — 은행 `grammar`에서 급수로. 문장에 빈칸, 보기 4개(은행의 순서를 코드가 섞는다).
- **독해** — 은행 `reading`. 지문은 `ClickableSentence`로 그리지 **않는다**(단어 탭으로 뜻을 보면
  진단이 안 된다). 결과 화면 해설에서만 붙인다.
- **청해** — 은행 `listening`. 6절 TTS 규칙.

### 4-4. 청해 (TTS)

- `SpeakButton`이 아니라 `useJapaneseSpeech`를 직접 쓰는 **전용 플레이어**가 필요하다(대사 여러
  줄, A/B 화자 사이 쉼, 재생 횟수 제한). 이건 "화면마다 useJapaneseSpeech를 새로 부르지 말 것"
  규칙의 예외로 CLAUDE.md에 이유와 함께 적을 것.
- 문제가 뜨면 **자동 재생하지 않는다**(모바일은 사용자 동작 없는 재생이 막힌다) — ▶ 버튼으로 시작.
- **두 번까지** 들을 수 있다. 재생 중에는 보기를 누를 수 있다.
- A/B 화자는 음성이 둘 이상이면 다른 목소리, 아니면 같은 목소리에 `pitch`만 다르게.
  `scoreVoice`의 순위를 그대로 쓰고 캐릭터 목소리는 제외한다.
- **일본어 음성이 없거나 `speechSynthesis`가 없으면 청해 영역을 건너뛰고** 결과에 "측정 안 함"으로
  표시한다. 0점으로 치지 말 것.
- 속도는 급수별로: N5·N4 0.9, N3 0.95, N2·N1 1.0.
- 진단을 떠나거나 다음 문제로 가면 `speechSynthesis.cancel()`.

### 4-5. 결과 화면 + 종합 판정 (`src/lib/levelTest/result.ts` — 순수 함수, 테스트 필수)

- 영역별 추정 급수를 막대/계단 그림으로(무채색은 `white`·`gray-*`만 — 다크 모드 규칙).
- **종합 급수** = 측정한 영역 추정치의 **중앙값**. 단 가장 낮은 영역이 중앙값보다 2단계 이상 낮으면
  한 단계 내린다(JLPT는 모든 영역 기준점을 넘어야 합격이다 — 한 영역이 크게 비면 그 급수는 위험).
  "측정 안 함" 영역은 빼고 계산한다.
- **신뢰도 안내** — 어떤 영역이 상한까지 갔는데도 방향 전환이 3번이 안 됐으면 "이 영역은 조금 더
  풀어봐야 정확해요"를 붙인다.
- 틀린 문제 해설(문법 `translation`·`note`, 어휘 정답 뜻, 한자 읽기가 든 단어). 여기서는
  `ClickableSentence` + `useSentenceDialogs`로 단어를 눌러볼 수 있다.
- **선생님 총평**(선택, AI 될 때만) — 코드가 만든 요약만 넘긴다:
  `영역별 급수 / 종합 / 영역별 정답 수 / 고른 공부 목적·시험 일정`. 3~5문장, 한국어, 다음에 무엇부터
  하면 좋을지 하나. 4중 방어 + 유출 검사 기준은 형식·예시를 뺀 지시문. 선생님 수업 세션과 분리된
  단발 세션. AI가 없으면 코드가 만든 고정 문구로 대신한다.
- 버튼:
  - **"이 단계부터 시작하기"** — `curriculumStore.setStartLevel(종합)`. 이미 시작 단계가 있으면
    "지금: N5 → 진단: N4, 바꿀까요?"로 한 번 묻는다. 진도(수동 완료 유닛)는 건드리지 않는다.
  - "선생님에게 결과 물어보기" — `teacherChatStore.requestQuestion()`으로 결과 요약을 담은 질문을
    보낸다(질문 문장은 코드가 만든다).
  - "처음 화면으로".
- XP: **진단 완주에 한 번**(`XP_REWARDS.levelTestCompleted` — 이름 충돌 주의: 기존 값을
  `unitCheckCompleted`로 바꾸고 새 키를 만든다). 다시 보기로는 하루 한 번까지만.

### 4-6. 저장과 연동

- 새 persist 스토어 `levelTestStore`(키 `level-test`) — 최근 진단 결과 **3개만**
  `{ takenAt, sections: {vocab, kanji, grammar, reading, listening, kana}, overall }`.
  **`BACKUP_LOCAL_KEYS`에 넣는다**(학습 이력이다 — CLAUDE.md "새 persist 스토어" 규칙).
  `parseBackup`이 모양을 검사하는지 확인하고 테스트에 한 줄 추가.
- 선생님 시스템 프롬프트의 학습자 정보(`promptMemory` 스냅샷)에 **최근 진단 한 줄**을 더한다:
  `레벨 진단(2026-10-08): 종합 N4 — 어휘 N3, 한자 N4, 문법 N4, 독해 N4, 청해 N5`.
  스냅샷 갱신 시점 규칙(명시적인 지점에서만)을 따른다 — 진단을 끝냈을 때 갱신.
  `looksLikePromptLeak`에는 여전히 고정 부분만 넘긴다.
- `learnerProfile.levelGuess`와 진단 결과가 둘 다 있으면 **진단이 이긴다**(최근 30일 이내일 때).
  `/test`·오늘의 추천·선생님 난이도가 같은 판단을 쓰게 한 곳(`effectiveLevel()` 같은 순수 함수)에서 고른다.
- 대문 "오늘의 학습": 시작 단계가 없을 때 진단을 권하는 항목. 마지막 진단이 90일 지났으면 한 줄
  "다시 진단해볼까요?"(강요하지 않음).

### 5-2. 출제 (`src/lib/unitCheck.ts` — 순수 함수, 테스트 필수. 기존 `levelTest.ts`를 대체)

## 10. 구현 결과 (2026-10-09) — 이 문서와 달라진 점

1~9단계를 모두 구현했다. 지금의 동작은 CLAUDE.md "레벨 진단" 절과 "선생님 `/` 명령어" 절이 기준이다.
이 문서와 다르게 간 곳:

- **독해·청해에서 통과한 급수가 없으면** Pre-N5가 아니라 "풀어 본 가장 낮은 급수의 한 칸 아래"로 추정하고
  신뢰도 낮음으로 표시한다(N1 지문부터 시작해 놓친 학습자가 "N5 전"이 되어 종합을 끌어내렸다).
- 상한까지 가고도 방향 전환이 3번 안 됐어도 **N1로 추정되면 신뢰도 높음** — 더 올라갈 급수가 없을 뿐이다.
- 종합 중앙값은 짝수 개일 때 **낮은 쪽**. 가나 영역은 3/4 미만이면 종합을 Pre-N5로.
- 일본어 모드의 `/level`은 `れゔぇl`이 아니라 **`ぇゔぇl`**로 들어온다(l로 시작하면 작은 가나). 그 때문에
  치는 도중의 목록이 끊겨, 명령어 비교에 "이름을 한 글자씩 늘려 가나로 바꾼 것"을 더했다.
- 단원 점검의 어휘는 "단원 몫"이 아니라 **단원 급수의 흔한 단어** — 커리큘럼이 단원에 단어를 묶지 않았다.
  문형이 적은 단원이 많아 **8문항까지 한자·어휘로 보충**하고, Pre-N5 단원은 가나·커리큘럼 낱말로 점검한다.
- XP: 진단 20(하루 한 번), 단원 점검 10(시트마다 첫 완주). 옛 `levelTestCompleted`는 `unitCheckCompleted`로.
- 선생님 총평은 모델이 **바로 쓸 수 있을 때(available)만** 부른다 — 총평 하나 때문에 모델 다운로드를 시작하지
  않는다. 유출이면 처음 30자쯤이 잠깐 보였다가 코드 총평으로 바뀐다(기존 가드의 성질).
- `PracticeTarget` 일반화는 그대로 뒀다(지금은 연습해보기만 쓴다).
